## Phase Goal

**As a** client of the rs3 HTTP API, **I want to** call every non-JavaScript route and get the same success bodies as before plus clear 4xx errors for missing keys and bad input, **so that** existing integrations keep working and bad requests can no longer crash the server.

This plan is the **input validation and listing slice**, and it closes the phase. After it, a malformed insert body answers a JSON 400, a wrong-shape body answers a JSON 422 and writes nothing, `/list` is correctly escaped in its legacy shape, the clippy gate forbids unwrap/expect outside tests, and the whole phase gate is green on the merged tree from plans 02-01 and 02-02.

<objective>
Split insert failures into 400 malformed_json and 422 invalid_input, reading the raw body bytes (D-03), with the error mapping in ApiError (D-01, D-02). Make the batch write infallible through insert_all and document partial-batch visibility (D-13, IN-03). Pin {} as a no-op and the 413 default (D-05). Escape `/list` with serde_json while keeping the legacy envelope (D-06..D-09). Turn on the unwrap/expect deny lints with their test allowances (D-13), and run the full phase gate.

Purpose: phase success criteria 1 (escaped `/list` round-trips) and 2 (400/422 with nothing inserted), plus the D-13 lint gate and the end-of-phase TOOL-03, TEST-01 and TEST-02 proof.

## Flagged Assumptions

- **Duplicate keys in one body:** serde_json with `preserve_order` keeps the first position and the last value (`{"a":"1","a":"2"}` becomes `[("a","2")]`, spike-verified). This is treated as the defined behaviour, pinned by `insert_duplicate_key_last_value_wins`, not rejected as invalid input.
- **413 body is text/plain:** actix's built-in 413 is not JSON (D-05). A JSON 413 and JSON unknown-route 404s are deferred to v2 (CONTEXT Deferred Ideas). Tests assert only the status.
- **Message wording:** the 422 message keeps the existing "value for key {k} must be a string" text, so the live smoke can check that it names the key (`key b`). Other message wording is at Claude's discretion and is never asserted exactly, except through the fixed `error` codes.
