## Phase Goal

**As a** developer on rs3, **I want to** build, lint and test the crate on Rust 1.99.1 with edition 2024 and only released dependencies on top of a modular store and config foundation, **so that** every later port lands on a compiling, current tree.

This plan is the **walking skeleton** (see `SKELETON.md` in this phase directory): the thinnest end-to-end rs3 on the new toolchain. After it, `cargo run` on Rust 1.99.1 starts the server from `SERVER.HOST`/`SERVER.PORT`, `GET /` answers, a key inserted with `POST /insert` comes back from `GET /key/{key}` through the papaya `Store`, and bad config exits 1. Plans 01-02 and 01-03 then expand it in parallel.

## File Budget Justification (scope_sanity)

This plan lists 15 paths (11 written, 4 deleted), and Task 1 touches 12 of them. That is over the more-than-5-files split rule. The overage is accepted on purpose rather than split, and `src/http/mod.rs` stays in Task 1. The reasons:

- **The old tree cannot compile in part.** D-04 removes `lazy_static`, `flurry`, `dotenv` and `rusty_v8` from the manifest. The old `src/main.rs` uses `flurry` and `lazy_static`. `src/bindings/mod.rs` uses `rusty_v8` and the removed `op_sync`. `src/config/mod.rs` uses `dotenv` and the removed `Config::new`. `src/services/mod.rs` depends on the legacy `crate::config::Config`, which D-12 replaces. Creating `src/config.rs` while `src/config/mod.rs` still exists is a hard error (E0761, Pitfall 5). So the manifest reset, the deletions and the new `lib.rs`/`main.rs`/`config.rs`/`js`/`http` modules must land together before `cargo build` can pass even once.
- **Task 1 is the walking-skeleton tracer.** Its `<verify>` must run the real binary and get `"Welcome to rs3"` from `GET /`, and `main.rs` calls `configure(rs3::http::configure)`. Without `src/http/mod.rs`, Task 1 has nothing to serve and no end-to-end check. Moving that file to Task 2 would also cut Task 1 only from 12 paths to 11, which is still over the rule.
- **Splitting into another plan would leave a broken tree at a wave boundary.** A plan holding only the toolchain, manifest and lock could not pass the TOOL-03 gate, because the crate would not compile until the restructure plan landed. D-20's ordering is about commits, and Task 1 already keeps it as commit A then commit B.
- **The real context cost is small.** The 4 deletions are `git rm` one-liners. `Cargo.lock` is generated by `cargo generate-lockfile`, not written by hand. Of the 7 authored files, `rust-toolchain.toml`, `src/lib.rs` and `src/js/mod.rs` are each under 10 lines, and the whole of Task 1 is about 150 authored lines, which fits the `estimate` above. Task 2 touches 5 files, within the rule.
