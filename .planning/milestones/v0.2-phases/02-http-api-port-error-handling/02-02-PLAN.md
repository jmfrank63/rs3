## Phase Goal

**As a** client of the rs3 HTTP API, **I want to** call every non-JavaScript route and get the same success bodies as before plus clear 4xx errors for missing keys and bad input, **so that** existing integrations keep working and bad requests can no longer crash the server.

This plan is the **configuration slice**. It covers the review findings WR-01 and WR-02 (operator directive) and IN-07. The server keeps reading `SERVER.HOST` / `SERVER.PORT` from a dotenv file or the environment. Loading no longer mutates the process environment, a broken dotenv file stops startup with a clear one-line error instead of being half-applied, and unrelated environment variables can no longer collide with the `server` table. Plan 02-01 runs in parallel and owns `main.rs` and `src/http/`.

Prove the paths in code without touching the real environment (TEST-02). Prove the env-only and no-config startup paths on the real binary.

Purpose: phase success criterion 3 (config loaded once, never re-read), plus the WR-01/WR-02 hardening the operator routed into Phase 2.
Output: src/config.rs.
