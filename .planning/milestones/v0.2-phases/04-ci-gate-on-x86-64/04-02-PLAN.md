## Phase Goal

**As a** maintainer of rs3, **I want to** gate every push with a GitHub Actions workflow on an x86_64 runner that fails on any fmt, clippy or test failure, **so that** regressions and x86-only V8 crashes are caught before they land.

This plan is the **x86_64 V8 evidence slice**. Plan 04-01 left a release smoke that only proves the binary starts and answers `GET /`. Task 1 makes it drive a stored script through `PATCH` on the release binary, which is the only build that uses the protected V8 platform, assert the 422 `js_error` path, and prove that a crash, a dead binary or a busy port fails loudly with its exit status. On the x86_64 runner, that step is where a PKU problem would show. Task 2 replays the whole gate locally, records it in the validation map, and hands the remote run to the operator as a pending UAT item. It does not push and does not invent a green result (D-09).

<objective>
Extend `scripts/ci-smoke.sh` with the D-06 JS assertions (insert, PATCH 6*20 = "120", PATCH of a throwing script = 422 js_error, GET / still 200 and the process alive) and prove its failure modes (missing binary, exiting binary, SIGSEGV = status 139, busy port). Then run the full D-08 local validation, mark the Phase 4 rows green in `04-VALIDATION.md`, and write the D-09 pending human UAT item, including the D-07 fallback, into the plan SUMMARY for the orchestrator to persist.

Purpose: CI-03's evidence path (the protected V8 platform exercised in the release binary, with a crash reported as status 139) and the honest handoff of the one thing this run cannot observe, the green remote x86_64 run. CI-02 stays intact: no server env in the workflow, and every gate passes locally.
Output: scripts/ci-smoke.sh (extended), .planning/phases/04-ci-gate-on-x86-64/04-VALIDATION.md (statuses), and 04-02-SUMMARY.md with the UAT handoff.
