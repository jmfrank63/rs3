## Phase Goal

**As a** user storing scripts in rs3, **I want to** PATCH a key and have its JavaScript run on current deno_core with the five store ops, **so that** the JS-executes-against-the-store behaviour works again and no script or op error can abort the server.

This plan is the **PATCH-over-HTTP slice**, and it closes the phase. It puts the plan 03-01 engine behind `PATCH /key/{key}`: `main` starts the pool once after the V8 platform, `AppState` carries it, and the handler only awaits it. Script failures become 422 `js_error` and host faults become 500 `internal`. The bundled samples from plan 03-02 run as fixtures, a PATCH of `op_rs3_list` is byte-equal to `GET /list`, every route has a byte-exact success test, and the deferred Phase 2 review items are folded in. The full phase gate runs on the merged tree.
