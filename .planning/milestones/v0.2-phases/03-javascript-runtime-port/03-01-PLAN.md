## Phase Goal

**As a** user storing scripts in rs3, **I want to** PATCH a key and have its JavaScript run on current deno_core with the five store ops, **so that** the JS-executes-against-the-store behaviour works again and no script or op error can abort the server.

This plan is the **JS engine slice**. It opens with the phase's riskiest assumption, reproduced in-repo as failing tests: a nested `JsRuntime` inside a `#[op2(reentrant)]` op, plus the `op_panic` abort guard. If that assumption turns out to be a dead end, the phase stops before anything else is built on it. After this plan, any caller in the crate can hand a script and a `Store` to a bounded pool of dedicated `rs3-js-*` threads and get back the stringified completion value or a typed script error, with all five store ops and no path a script can use to abort the process. Plan 03-03 then puts this engine behind `PATCH /key/{key}`.

All of this runs on a bounded pool of named 16 MiB threads, each with a tokio current_thread runtime and catch_unwind per job (D-05, D-06, D-11), with a shared cfg(test) executor and the dev-only unprotected platform (D-07, D-08). tokio is the only new direct dependency (D-09).

deno_core 0.412.0 / deno_error 0.7.1 / tokio 1.54.0 facts (verified against the registry sources and the research spike):
- `deno_core::extension!(rs3_ext, ops = [..], options = { ctx: ExecCtx }, middleware = |op| .., state = |state, options| { .. });`: the parameters go in that order. Registration is `rs3_ext::init(ctx)`. `OpDecl::disable(self) -> Self` turns an op into one that throws `Error: op is disabled`. The middleware also applies to deno_core's own built-in ops.
- `#[op2]` / `#[op2(reentrant)]`, `#[string]` on a String return and on a String argument, `state: &mut OpState`, `state.borrow::<ExecCtx>()`, return type `Result<String, deno_error::JsErrorBox>`.
- `JsErrorBox::generic(msg)` gives a JS `Error`, and `JsErrorBox::type_error(msg)` gives a JS `TypeError`. Use only these built-in classes.
- `JsRuntime::try_new(RuntimeOptions { extensions: vec![..], ..Default::default() }) -> Result<JsRuntime, CoreError>`. The other constructor panics on bootstrap failure, so do not use it.
- `execute_script(name: impl IntoModuleName /* String ok */, source: impl IntoModuleCodeString /* String ok */) -> Result<v8::Global<v8::Value>, Box<JsError>>`. `JsError` has `pub exception_message: String`. Its Display includes the stack.
- `deno_core::scope!(scope, &mut rt);` enters the main context. Then `deno_core::v8::Local::new(scope, global).to_rust_string_lossy(scope)`.
- `deno_core::JsRuntime::init_platform` uses an internal Once, and the protected/unprotected choice is `cfg!(any(test, feature = "unsafe_use_unprotected_platform"))` inside deno_core.
- tokio: `runtime::Builder::new_current_thread().enable_all().build()`, `rt.enter()`, `rt.block_on(..)`, `sync::mpsc::channel(cap)` (panics when cap is 0), `sync::oneshot`, `sync::Mutex`. `mpsc::Sender<T>` implements Debug without a `T: Debug` bound.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored script -> V8 isolate | Any client can store a value that later runs as JavaScript; the script is untrusted code |
| JS -> Rust ops | Op arguments come from untrusted script code and cross into Rust through the extern op boundary, where a panic is a process abort |
| job submitter -> rs3-js pool | Jobs from many callers share a fixed set of worker threads |
