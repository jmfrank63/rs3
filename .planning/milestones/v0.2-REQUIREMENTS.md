# Requirements: rs3

**Defined:** 2026-10-20
**Core Value:** rs3 builds, tests and lints cleanly on current stable Rust (edition 2024) with only released dependencies — while every existing HTTP route and the JS-executes-against-the-store behaviour keep working with the same semantics.

## v1 Requirements

Requirements for the modernization milestone. Each maps to roadmap phases.

### Toolchain

- [x] **TOOL-01**: Developer running any `cargo` command in the repo gets Rust 1.99.1 with `rustfmt` and `clippy` via `rust-toolchain.toml`; the legacy `rust-toolchain` file is deleted
- [x] **TOOL-02**: `Cargo.toml` declares `edition = "2024"` and `rust-version = "1.99"`
- [x] **TOOL-03**: `cargo build`, `cargo test`, `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` all pass on a clean checkout

### Dependencies

- [x] **DEPS-01**: All dependencies are released crates.io versions — no git, path or pre-release (beta/rc) dependencies
- [x] **DEPS-02**: `Cargo.lock` is regenerated from scratch and `cargo tree -d` shows a single V8 (no direct `v8`/`rusty_v8` dependency; `deno_core::v8` used)
- [x] **DEPS-03**: `lazy_static`, `dotenv` and `flurry` are removed (replaced by injected state / `LazyLock`, `dotenvy`, and a maintained concurrent map such as `papaya`)
- [x] **DEPS-04**: Configuration uses the current `config` crate builder API and still reads `SERVER.HOST` / `SERVER.PORT` from `.env` or the environment

### Architecture

- [x] **ARCH-01**: Code is split into separate store, JS runtime, HTTP and config modules (`lib.rs` + thin `main.rs`, single package) with dependencies pointing one way (http → js → store)
- [x] **ARCH-02**: The store is created once in `main` and injected into HTTP handlers (`web::Data`) and JS ops (`OpState`); there is no global map
- [x] **ARCH-03**: Config is loaded once at startup and injected; handlers do not re-read the environment per request
- [x] **ARCH-04**: Startup errors (bad config, port bind failure) are reported and exit non-zero instead of panicking

### HTTP API

- [x] **HTTP-01**: `GET /` returns 200 with body `"Welcome to rs3"` (byte-identical to before)
- [x] **HTTP-02**: `GET /ip` returns 200 with the configured host in the existing body format
- [x] **HTTP-03**: `POST /insert` with a JSON object of string values inserts every pair and echoes the object in the existing body format
- [x] **HTTP-04**: `GET /list` returns all entries in the existing list shape, with keys/values correctly JSON-escaped
- [x] **HTTP-05**: `GET /key/{key}` returns the value for an existing key in the existing body format
- [x] **HTTP-06**: `DELETE /key/{key}` removes an existing key and returns its old value
- [x] **HTTP-07**: `PATCH /key/{key}` executes the stored value as JavaScript and returns the stringified completion value
- [x] **HTTP-08**: Handlers are ported to the current actix-web 4.x release API (`#[actix_web::main]`, `#[actix_web::test]`, current test utilities)

### Robustness

- [x] **ROBU-01**: `GET`, `DELETE` or `PATCH` on a missing key returns 404 with a JSON error body (no panic; replaces the old `"[]"` on empty store)
- [x] **ROBU-02**: `POST /insert` with malformed JSON returns 400; valid JSON that is not an object or contains non-string values returns 422; nothing is inserted on error
- [x] **ROBU-03**: `PATCH` on a script that throws or has a syntax error returns 422 with a JSON error body containing the JS error message
- [x] **ROBU-04**: No `unwrap()`/`expect()` on request-dependent data in handlers, store or ops; ops return errors to JS instead of panicking (an op panic would abort the process)
- [x] **ROBU-05**: A script that recursively PATCHes itself (directly or via a cycle) is stopped by a nesting depth limit and returns 422 instead of crashing the server
- [x] **ROBU-06**: A non-terminating script (e.g. `while(true){}`) is terminated after a configurable timeout and returns 504; the server keeps serving other requests

### JavaScript Runtime

- [x] **JSRT-01**: The embedded engine uses current released `deno_core` with ops defined via `#[op2]` and registered through `extension!`
- [x] **JSRT-02**: JS can call five store ops — `Deno.core.ops.op_rs3_list()`, `op_rs3_get(key)`, `op_rs3_insert(json)`, `op_rs3_delete(key)`, `op_rs3_patch(key)` — with the same semantics as the old `rs3_*` ops
- [x] **JSRT-03**: A missing key or invalid input inside an op surfaces as a catchable JS exception, not a process abort
- [x] **JSRT-04**: JS execution runs off the actix worker threads (dedicated JS threads) with V8 platform initialised once in `main` before other threads spawn
- [x] **JSRT-05**: All JS artefacts (`requests/*.js`, `requests/*.txt`, `requests/*.http`, `src/example.js`, test scripts) use the new `Deno.core.ops.op_rs3_*(...)` syntax with `Deno.core.ops();` calls removed
- [x] **JSRT-06**: The old→new op name mapping is documented

### Testing

- [x] **TEST-01**: Tests use an isolated store per test (no shared global state, no `thread::sleep`) and pass deterministically under parallel `cargo test`
- [x] **TEST-02**: Tests do not depend on process environment variables (config is constructed in code)
- [x] **TEST-03**: Each route has a success test asserting status and preserved body bytes
- [x] **TEST-04**: Each error path (404, 400, 422 insert, 422 JS exception, depth limit, timeout) has a test
- [x] **TEST-05**: The sample programs (`fac.js`, `sum.js`, `bin.js`) run as test fixtures and produce expected results
- [x] **TEST-06**: A test confirms PATCH running `op_rs3_list` returns the same content as `GET /list`

### CI

- [x] **CI-01**: GitHub Actions workflow uses `actions/checkout` v4+, `dtolnay/rust-toolchain` and `Swatinem/rust-cache`; the archived `actions-rs/*` workflow is removed
- [x] **CI-02**: CI runs fmt check, clippy (`--all-targets -D warnings`) and tests with `--locked`, and any failure fails the build (no `continue-on-error`)
- [x] **CI-03**: CI runs on an x86_64 Linux runner and passes (catches V8 platform/PKU issues not visible on aarch64) (implemented; remote x86_64 evidence: GitHub Actions run 39507141932 green on ubuntu-26.04 for operator commit fd8f43f — 171 tests at default threads, release smoke incl. PATCH "120" and 422 on the protected V8 platform; the hardened Phase 4 scripts then ran green remotely in run 39527188207 at 40afeb7 (0 annotations, 216 tests), recorded as 04-UAT item 1, passed)

### Deployment

- [x] **DEPL-01**: The obsolete container deployment is removed: the root `Dockerfile` and the `docker_rs3/` directory are deleted (the MSc-era version stays at git tag `msc`), no `.dockerignore` is added, and the docs, requirements and CI scripts no longer refer to it
- [x] **DEPL-02**: `Readme.md` documents the native release build (`cargo build --release --locked`) and a short install section for running the binary on a single Linux server
- [x] **DEPL-03**: An example hardened systemd unit (`deploy/rs3.service`) runs rs3 as an unprivileged user, takes `SERVER.HOST` / `SERVER.PORT` from an `EnvironmentFile`, restarts on failure, and applies sandboxing directives compatible with V8

### Documentation

- [x] **DOCS-01**: `Readme.md` documents the toolchain (Rust 1.99.1 / edition 2024), first-build V8 note, configuration (`SERVER.HOST` / `SERVER.PORT`), and build/run/test instructions
- [x] **DOCS-02**: `Readme.md` documents the new JS op syntax with the old→new op mapping and an example, linking `docs/js-ops.md`
- [x] **DOCS-03**: `Readme.md` documents the HTTP API with its error status codes and a "Behaviour changes" section versus the 2021 version (sorted and escaped `/list`, 404 instead of `"[]"` for missing keys, 400/422 inserts and other 4xx errors, op renames, PATCH depth limit and timeout)
- [x] **DOCS-04**: `Cargo.toml` declares `license = "MIT"` and `Readme.md` states the MIT license

## Out of Scope

| Feature | Reason |
|---------|--------|
| Changes to `experiments/`, `aws/`, `Vagrantfile` | Explicitly excluded by the brief; the one exception is the deleted stale `experiments/web_scrape_s3_api/Cargo.lock` (it triggered Dependabot alerts) |
| Container image deployment | Dropped on 2026-10-21 by user decision: rs3 ships as a native binary on a single Linux server (see PROJECT.md Key Decisions) |
| `web::Json` extractor for `/insert` | Rejects requests without a JSON content-type (breaks `curl -d`) and collapses the 400/422 split |
| Reusing one `JsRuntime` across requests | Top-level `let` collisions between scripts (e.g. `fac.js` fails on second run); state leaks between requests |
| `deno_runtime` / fs / net APIs in the JS sandbox | Expands attack surface; not needed for store ops |
| Back-compat shim for `Deno.core.opSync` | Old API removed upstream; clean migration with documented mapping instead |
| Workspace split into multiple crates | Single package required; each extra test binary re-links V8 |
| Persistence / new store features | Modernization milestone, not a feature milestone |
| musl / fully static builds | The V8 prebuilt static libs used here target glibc |
