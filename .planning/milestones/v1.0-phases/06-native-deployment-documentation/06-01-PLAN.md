## Phase Goal

**As a** new developer or operator of rs3, **I want to** build it as a native binary, run it on a single Linux server under an example hardened systemd unit, and learn the toolchain, configuration, HTTP API, JS op syntax and behaviour changes from the README, **so that** I can build, deploy and extend the modernized server without reading the source.

This plan is the **native deployment slice**. Task 1 is the tracer. It adds the MIT license line, the unit and its env file, and a Deployment section in the README, and then proves the whole path: release build, the unit's own ExecStart and EnvironmentFile under a real systemd (user manager), and GET / plus a PATCH through V8 with seccomp active. Task 2 proves and documents the failure modes an operator meets: a seccomp kill-action run with nested PATCH, the depth limit and the timeout; the start limit on a broken env file; and a missing env file. It also hands the root-only checks to the operator. Task 3 removes the container deployment that the unit replaces, re-words the brief, and runs the full CI gate. Plan 06-02 then writes the developer-facing README sections around this one.
