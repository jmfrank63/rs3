## Phase Goal

**As a** user storing scripts in rs3, **I want to** PATCH a key and have its JavaScript run on current deno_core with the five store ops, **so that** the JS-executes-against-the-store behaviour works again and no script or op error can abort the server.

Every script that ships with rs3 (the samples in `requests/`, their JSON-escaped `/insert` payloads, the REST-client walkthroughs and `src/example.js`) moves to `Deno.core.ops.op_rs3_*` without changing what it computes. `docs/js-ops.md` becomes the one place a user looks up how an old script maps to the new ops, what throws, what PATCH returns, and which limits remain until Phase 5.
