## Phase Goal

**As a** client of the rs3 HTTP API, **I want to** call every non-JavaScript route and get the same success bodies as before plus clear 4xx errors for missing keys and bad input, **so that** existing integrations keep working and bad requests can no longer crash the server.

This plan is the **injected state and JSON error contract slice**. After it, the store and settings live in one `AppState` created in `main`, every route reads it through `web::Data`, a missing key on GET, DELETE or PATCH answers a JSON 404 instead of panicking or returning the empty-store string, and every test owns its own state. Plan 02-02 hardens config loading in parallel. Plan 02-03 then adds the 400/422 insert split, the escaped `/list` and the unwrap/expect lint gate.

## Flagged Assumptions

Spec-less edge probe rows that stayed `unclassified` / `unresolved` (surfaced, not dropped):

- **HTTP-01 (unclassified):** `GET /` ignores the query string and request headers (including `content-type`) and always returns the same 200 body. The golden test is taken to be the full contract, and no further edge applies.
- **HTTP-02 (unclassified):** "configured host" means the `SERVER.HOST` string exactly as loaded at startup: no DNS resolution, no normalisation, and not the bound socket address. It is interpolated unescaped into the legacy `{'IP' : '<host>'}` text, which is then JSON-encoded. A host containing a quote gives odd but valid JSON. This is accepted because the host is chosen by the operator.
- **HTTP-05 (unclassified):** the `{key}` path segment is percent-decoded by actix's `Path` extractor. A key containing `/` cannot be addressed through `GET /key/{key}` (one segment). This matches legacy behaviour and is not changed.
- **TEST-02 (unclassified):** "do not depend on process environment variables" means no test reads or writes `SERVER.*` and no test relies on a dotenv file. Tests may still inherit `PATH`/`HOME` for cargo itself. Proven by running the suite under `env -i PATH HOME`.
- **A2 (research):** no ancestor directory holds a dotenv file that breaks startup. The secret-file guard forbids probing for one; see the `<environment>` note.

Prohibition recall (spec-less §B): one bespoke prohibition was kept (gate integrity, above). Canon items were dropped with breadcrumbs: error-body information disclosure, and injection through echoed keys, are canon and covered by /gsd-secure-phase. They are not minted here, and the threat register below covers them.
