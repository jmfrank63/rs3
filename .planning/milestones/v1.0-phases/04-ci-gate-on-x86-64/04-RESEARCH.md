# Phase 4: CI Gate on x86_64 - Research

**Researched:** 2026-10-20
**Domain:** GitHub Actions CI for a Rust + V8 (deno_core) crate; repo guard scripts; release-binary smoke
**Confidence:** HIGH. Every action ref was checked against the GitHub API, and every script was prototyped and run locally on this aarch64 host, both on the current tree and against planted violations. The only unobservable item is the remote x86_64 run, which needs a push and is recorded as UAT.

## Summary

This is a small infrastructure phase. One workflow, `.github/workflows/ci.yml`, has a single `ci` job on `ubuntu-24.04`. The steps are checkout, toolchain, rust-cache, then the guards, fmt, clippy, test, the release build and the release smoke. `.github/workflows/actions-rs.yml` is deleted. Two bash scripts and one optional Python checker carry the logic, so every gate can be reproduced locally with no push. All three action refs exist today: `actions/checkout@v7` (latest v7.0.1), the `dtolnay/rust-toolchain` branch `1.99.1`, and `Swatinem/rust-cache@v2` (v2.9.3, released today). The runner image ships curl 8.5 and Python 3.12.3, which is what the v8 build script needs to download its prebuilt library. The x86_64 prebuilt asset that build script will fetch (`librusty_v8_simdutf_release_x86_64-unknown-linux-gnu.a.gz`, 38.8 MB) exists in the v150.4.0 release.

Two findings change how the plan should look. (1) **rust-cache needs no tuning.** Its cleanup deletes `target/<profile>/gn_out`, where `librusty_v8.a` lives, but I confirmed by experiment that the V8 static library is bundled into the `libv8-*.rlib`. A relink with `gn_out` removed succeeded, and the resulting binary passed the smoke. The estimated cache is about 3.3 GB uncompressed, well under the 10 GB repository limit. Do not add `save-if` restricted to `main`, because that would leave every `modernize-toolchain` run cold. (2) **The guards must be written to tolerate known noise.** `cargo test` reports `1 ignored`. That comes from a `rust,ignore` doctest generated by deno_core's `extension!` macro, not from rs3 code, so a guard that greps test output for "ignored" would always fail. Source greps are the right tool. Likewise `cargo tree -d` already lists same-version duplicates (`libc`, `serde`, …, split by host and target), so the v8 guard must filter on `^(v8|rusty_v8) v` rather than "any duplicates".

**Primary recommendation:** Copy the prototypes in this document as they are. They passed on the simulated post-phase tree and caught every planted violation. Invoke the scripts as `bash scripts/…` in the workflow so the git mode bit cannot break CI. Record the remote run as UAT under D-09.

### Pattern 1: Logic lives in scripts, the workflow only sequences them
**What:** Every `run:` is a single command that also works locally. **When:** always. Local validation is required because pushing is forbidden.

### Pattern 2: A guard collects every failure, then exits
**What:** Each guard prints `ok [x]` or `FAIL [x] <hits>`, and the script exits 1 if any guard failed. **Why:** a single CI run shows every violation. The tags `[a]`…`[h]` map one-to-one to D-05, which lets tests assert which guard fired.

### Anti-Patterns to Avoid
- **Greping `cargo test` output for `ignored`.** Today's output has `1 ignored` from a deno_core macro doctest (`deno_core-0.412.0/extensions.rs - js::ops::rs3_ext (line 486) ... ignored`) [VERIFIED: local `cargo test --locked --doc`]. Use source greps instead.
- **"No duplicates at all" on `cargo tree -d`.** It already lists `actix-router`, `bitflags`, `libc`, `memchr`, `serde`, `serde_core`, `smallvec`, `syn` (v2.0.119 and v3.0.9), `tracing` and `tracing-core` [VERIFIED: local run]. Filter on `^(v8|rusty_v8) v`.
- **Putting the literal `SERVER.` or `continue-on-error` in a `ci.yml` comment.** Guard (g) greps the whole file, comments included. Word the D-07 comment without those tokens (see the skeleton).
- **`export SERVER.HOST=…` in bash.** That is not a valid identifier. Use `env -i PATH="$PATH" SERVER.HOST=… SERVER.PORT=… bin`.
- **A fixed smoke port.** On this host something non-HTTP listens on `127.0.0.1:18081` (curl: "Received HTTP/0.9"), which shows that collisions really happen. Pick a free port with Python and probe it with `/dev/tcp` first.

## Common Pitfalls

### Pitfall 1: x86_64 PKU / protected-platform crash in the release binary
**What goes wrong:** V8's protected platform uses memory protection keys on x86 CPUs that support PKU. Isolates on threads that lack key access segfault.
**Why:** rs3 tests use the dev-only `unsafe_use_unprotected_platform` feature, so only the release binary takes the protected path. It initializes the platform on `main` before spawning threads (JSRT-04), which *should* be safe. That has never been observed on x86 [ASSUMED, matching 03-RESEARCH A1].
**How to avoid / detect:** `ci-smoke.sh` fails fast with `server exited during startup (status 139)`. A simulated SIGSEGV binary produced exactly that line [VERIFIED: local run]. The fallback under D-07 is to move the feature into `[dependencies]` (Cargo.toml line 27 already says so) and relax guard (d).

### Pitfall 2: The scripts lose their executable bit
**What goes wrong:** `run: scripts/ci-guards.sh` fails with exit 126 "Permission denied". This happened to my prototype.
**How to avoid:** call them as `bash scripts/…` in `ci.yml`, *and* `chmod +x` before `git add`. `core.fileMode=true` on this repo, so git records 100755. Check with `git ls-files -s scripts/`.

### Pitfall 3: PyYAML loads `on:` as the boolean `True`
**What goes wrong:** `wf["on"]` raises KeyError. PyYAML implements YAML 1.1, so the bare `on` becomes a boolean [VERIFIED: `yaml.safe_load('on:\n  push:\n…')` → `{True: {'push': None, …}}`].
**How to avoid:** `triggers = wf.get("on", wf.get(True))`. Note that `push:` with no value loads as `None`, meaning all branches.

### Pitfall 4: The cold-cache V8 download and disk space
**What:** On a cold cache, each profile runs the v8 build.rs, which downloads `librusty_v8_simdutf_release_x86_64-unknown-linux-gnu.a.gz` (38,799,023 bytes) plus `src_binding_simdutf_release_x86_64-unknown-linux-gnu.rs` from GitHub releases, using deno, then python, then curl [VERIFIED: GitHub API release v150.4.0 assets; v8-150.4.0 build.rs:791-836]. Locally, `target/` is about 3.1 GB debug (build, .fingerprint, deps, including spike leftovers) plus 0.8 GB release. The runner has 14 GB of documented SSD. That is enough, but expect the first run to take noticeably longer than cached runs. The 45-minute timeout leaves plenty of headroom (the local cold build took about 1.5 minutes on aarch64; the runner has only 4 vCPUs) [ASSUMED for runner timing].
**Warning signs:** "No space left on device" or a build.rs download failure. The fallback is `RUSTY_V8_MIRROR`/`RUSTY_V8_ARCHIVE` (build.rs:704-709); none is needed now.

### Pitfall 5: rust-cache cleanup deletes `target/*/gn_out`
**What:** rust-cache's `cleanProfileTarget` keeps only `build`, `.fingerprint` and `deps` [VERIFIED: rust-cache v2 `src/cleanup.ts`]. `librusty_v8.a` lives in `target/<profile>/gn_out/obj/` (build.rs:720-731).
**Why it is harmless:** the static library is bundled into `deps/libv8-*.rlib` (195,633,644 bytes against the 184,763,082-byte `.a`). With `gn_out` moved away and the rs3 binary deleted, `cargo build --release --locked` showed `Fresh v8`, relinked rs3 in 4.7 s, and the smoke passed [VERIFIED: local experiment]. **No `cache-directories` or other rust-cache tuning is needed.**

### Pitfall 6: `continue-on-error` inside third-party actions
`dtolnay/rust-toolchain`'s composite `action.yml` has `continue-on-error: true` on its internal `rustup default` step (issue #127) [VERIFIED: raw action.yml]. CI-02 applies to *our* workflow file, so this is fine. Guard (g) only scans `.github/workflows/`. Mention it in the verification so a reviewer isn't surprised.

### Pitfall 7: The dotenv file and the smoke environment
`Settings::load` reads a dotenv file from the current directory or its ancestors, and the process env wins (src/config.rs header). There is none in the repo root today, and CI never has one. `env -i` makes the process env hermetic, and the dotenv layer cannot override it.

### Pitfall 8: Double runs on same-repo pull requests
A push to a branch with an open PR runs twice: `refs/heads/x` and `refs/pull/N/merge` are different concurrency groups. That is acceptable and costs nothing for a public repo. Don't "fix" it by dropping `pull_request`, because D-03 locks both triggers.

### `scripts/ci-guards.sh`
```bash
#!/usr/bin/env bash
# Repo guard checks for CI (and local use). Exits non-zero if any guard fails.
set -euo pipefail
ROOT="${CI_GUARDS_ROOT:-$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)}"
cd "$ROOT"

failures=0
fail() { echo "ci-guards: FAIL [$1] $2" >&2; failures=$((failures + 1)); }
pass() { echo "ci-guards: ok   [$1] $2"; }

# Rust source roots to scan (src/ always; future dirs if they appear).
rs_roots=(src)
for d in tests benches examples build.rs; do [[ -e $d ]] && rs_roots+=("$d"); done

# (a) no lint-suppression attributes
if hits=$(grep -rnE '#!?\[[[:space:]]*(allow|expect)[[:space:]]*\(|cfg_attr[[:space:]]*\(.*\b(allow|expect)[[:space:]]*\(' "${rs_roots[@]}"); then
  fail a "lint-suppression attribute found:"$'\n'"$hits"
else pass a "no #[allow]/#![allow]/#[expect]/cfg_attr(..allow..)"; fi

### `scripts/check-workflow.py`
```python
#!/usr/bin/env python3
"""Structural check of .github/workflows/ci.yml (no actionlint on this host)."""
import sys
import yaml

PATH = ".github/workflows/ci.yml"
EXPECTED_USES = [
    "actions/checkout@v7",
    "dtolnay/rust-toolchain@1.99.1",
    "Swatinem/rust-cache@v2",
]
REQUIRED_RUNS = [
    "bash scripts/ci-guards.sh",
    "cargo fmt --check",
    "cargo clippy --all-targets --locked -- -D warnings",
    "cargo test --locked",
    "cargo build --release --locked",
    "bash scripts/ci-smoke.sh",
]

def main() -> int:
    with open(PATH, encoding="utf-8") as f:
        wf = yaml.safe_load(f)
    errs = []
    # PyYAML implements YAML 1.1: the bare key `on` loads as boolean True.
    triggers = wf.get("on", wf.get(True))
    if not isinstance(triggers, dict) or "push" not in triggers or "pull_request" not in triggers:
        errs.append(f"triggers must include push and pull_request, got {triggers!r}")
    elif triggers.get("push") not in (None, {}):
        errs.append("push trigger must not be filtered (all branches)")
    if wf.get("permissions") != {"contents": "read"}:
        errs.append(f"permissions must be {{contents: read}}, got {wf.get('permissions')!r}")
    conc = wf.get("concurrency") or {}
    if conc.get("cancel-in-progress") is not True or not conc.get("group"):
        errs.append("concurrency group with cancel-in-progress: true required")
    if (wf.get("env") or {}) != {"CARGO_TERM_COLOR": "always"}:
        errs.append(f"workflow env must be only CARGO_TERM_COLOR, got {wf.get('env')!r}")
    jobs = wf.get("jobs") or {}
    if list(jobs) != ["ci"]:
        errs.append(f"exactly one job 'ci' expected, got {list(jobs)}")
    job = jobs.get("ci") or {}
    if job.get("runs-on") != "ubuntu-24.04":
        errs.append(f"runs-on must be ubuntu-24.04, got {job.get('runs-on')!r}")
    if job.get("timeout-minutes") != 45:
        errs.append("timeout-minutes: 45 required")
    for scope, obj in [("job", job)] + [(f"step {i}", s) for i, s in enumerate(job.get("steps") or [])]:
        if "continue-on-error" in obj:
            errs.append(f"{scope}: continue-on-error is forbidden")
        if "env" in obj:
            errs.append(f"{scope}: env is forbidden (tests are env-free)")
    steps = job.get("steps") or []
    uses = [s["uses"] for s in steps if "uses" in s]
    if uses != EXPECTED_USES:
        errs.append(f"uses must be exactly {EXPECTED_USES} in order, got {uses}")
    for s in steps:
        if s.get("uses", "").startswith("dtolnay/rust-toolchain"):
            comps = {c.strip() for c in str((s.get("with") or {}).get("components", "")).split(",")}
            if not {"rustfmt", "clippy"} <= comps:
                errs.append("dtolnay/rust-toolchain needs components: rustfmt, clippy")
    runs = [s["run"].strip() for s in steps if "run" in s]
    pos = [runs.index(r) if r in runs else -1 for r in REQUIRED_RUNS]
    for r, p in zip(REQUIRED_RUNS, pos):
        if p < 0:
            errs.append(f"missing run step: {r!r}")
    if all(p >= 0 for p in pos) and pos != sorted(pos):
        errs.append(f"run steps out of order: {runs}")
    if any("actions-rs/" in u for u in uses):
        errs.append("actions-rs/* is forbidden")
    for e in errs:
        print(f"check-workflow: {e}", file=sys.stderr)
    return 1 if errs else 0

if __name__ == "__main__":
    sys.exit(main())

```bash
#!/usr/bin/env bash
# Release-binary smoke for CI and local use. Exercises the production (protected)
# V8 platform path: target/release/rs3 is built without dev-dependency features.
set -euo pipefail
ROOT="${CI_SMOKE_ROOT:-$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)}"
cd "$ROOT"
BIN="${RS3_BIN:-target/release/rs3}"
PORT="${RS3_SMOKE_PORT:-$(python3 -c 'import socket; s=socket.socket(); s.bind(("127.0.0.1", 0)); print(s.getsockname()[1])')}"
BASE="http://127.0.0.1:${PORT}"
LOG="$(mktemp)"

fail() { echo "ci-smoke: FAIL: $*" >&2; echo "--- server log ---" >&2; cat "$LOG" >&2 || true; exit 1; }

[[ -x "$BIN" ]] || fail "$BIN missing; run cargo build --release --locked first"
if (exec 3<>"/dev/tcp/127.0.0.1/${PORT}") 2>/dev/null; then fail "port ${PORT} already in use"; fi

# Config only through the process environment; bash cannot export dotted names, so use env.
env -i PATH="$PATH" SERVER.HOST=127.0.0.1 SERVER.PORT="$PORT" "$BIN" >"$LOG" 2>&1 &
PID=$!
cleanup() { kill "$PID" 2>/dev/null || true; wait "$PID" 2>/dev/null || true; rm -f "$LOG"; }
trap cleanup EXIT

# Readiness: poll until GET / answers; fail fast (with the exit status) if the server dies,
# e.g. a V8 platform segfault on x86_64 shows up as status 139 here.
body=""
for _ in $(seq 1 60); do
  if ! kill -0 "$PID" 2>/dev/null; then
    status=0; wait "$PID" || status=$?
    fail "server exited during startup (status ${status})"
  fi
  if body=$(curl -s --fail --max-time 2 "$BASE/"); then break; fi
  sleep 0.5
done
[[ -n "$body" ]] || fail "server not ready on ${BASE} after 30s"
[[ "$body" == '"Welcome to rs3"' ]] || fail "GET / body: ${body}"

# req METHOD PATH [BODY] -> sets CODE and BODY
req() {
  local out
  out=$(curl -sS --max-time 30 -w $'\n%{http_code}' -X "$1" ${3:+--data-binary "$3"} "$BASE$2") \
    || fail "$1 $2: transport error"
  CODE="${out##*$'\n'}"; BODY="${out%$'\n'*}"
}

req POST /insert '{"m":"6*20","boom":"throw new Error(\"boom\")"}'
[[ "$CODE" == 200 ]] || fail "POST /insert -> ${CODE} ${BODY}"
req PATCH /key/m
[[ "$CODE" == 200 && "$BODY" == '"120"' ]] || fail "PATCH /key/m -> ${CODE} ${BODY}"
req PATCH /key/boom
[[ "$CODE" == 422 && "$BODY" == '{"error":"js_error","message":"Uncaught Error: boom"}' ]] \
  || fail "PATCH /key/boom -> ${CODE} ${BODY}"
req GET /
[[ "$CODE" == 200 && "$BODY" == '"Welcome to rs3"' ]] || fail "GET / after JS error -> ${CODE} ${BODY}"
kill -0 "$PID" 2>/dev/null || fail "server died after JS error"
echo "ci-smoke: OK (${BIN}, port ${PORT})"
```
